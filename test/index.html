    Decision Support System for Key Account HO

    Current task load

    CPRs each KA is holding right now (Sequence 3, Sequence 8, Rework).

    Open tasks per KA

    Open task = a CPR that is still the KA's responsibility: waiting for the KA at Sequence 3 or 8, in rework, or approved by the KA at Sequence 8 but still with Purchasing Head HO / Director. TAT (turnaround time) is counted per KA step in calendar days: Sequence 3 = arrival at KA until the KA approves it; Sequence 8 = return to KA until the KA approves it. "So far" = not approved yet, counted until the data date. Targets: Sequence 3 at most 1 day (green), more = red; Sequence 8 up to 5 days green, 6–14 days yellow, more than 14 days red. The coloured counts are the open CPRs at that step. Click a Key Account, a bar or "Show CPRs" to list them.

    Task weights (current task load)
    Used only for the "Current task load" chart: how heavy the CPRs a KA is holding right now are. Default from CPRHistory Jan–Oct 2026 (median time at the KA, Sequence 3 = 1): Sequence 8 about 2.4–3× Sequence 3, Rework about 0.9×. Not used for the daily workload of the allocation, because the longer time at the KA is already counted there.

    Rework per KA

    Rework = a CPR sent back to the KA for correction (by Purchasing Head HO or Purchasing Director). Lower is better.

    Rework rate per KA (%)

    Only reworks caused by a KA error count. In brackets: CPRs with a KA-error rework / CPRs completed by the KA.

    Hover over a bar to see the reworked CPR numbers; click a bar or a Key Account name to list them all.

    CPRs requiring action

    "Auto-rejected" = a CPR still in progress, at any sequence, that shows no activity (no approval step in CPRHistory) for more than 30 days: the approval system rejects such CPRs automatically. It is marked automatically, is not counted as KA workload, is counted under "Rejected" in the Overview, and its data is kept; it becomes active again as soon as a new upload shows activity. Auto-rejected CPRs are excluded from "All active items". Select "Dismiss" to remove any CPR from this list and from the KA workload by hand; it can be restored at any time.

    Rule: a CPR can be reassigned at any stage. The reassignment form shows the CPR's current stage: after Sequence 3 is completed, the new KA handles Sequence 8. Automatic reassignments (absence, workload limit) still apply only to CPRs on which work has not started.

    KA absences

    An absent KA receives no new CPRs, and that KA's CPRs on which work has not started are reassigned automatically.

    KA replaced (left the team)

    When a KA leaves, the CPRs still in progress under that KA go to the replacement and are fixed there; completed work stays under the former KA's name in KA Performance.

    Reassignment log

    Every reassignment is recorded: when, which CPR, from whom, to whom, the reason, and by whom.

    1. Is the forecast accurate?

    Same test as the analysis notebook: the model learns only from history before the last 3 months, then forecasts the CPRs of those 3 months (2026 process). These CPRs were never used to choose or train the tested model, so this is an out-of-sample test.

    Check the forecast CPR by CPR (test months)

    Every CPR below was forecast by a model that had never seen it (it learned only from older CPRs), so this is how the forecast really performs. Use the groups to find where it misses most: a positive average difference = the forecast was too long, negative = too short.

    KA workload per day: forecast vs actual (test months)

    For every CPR created in the test months, the four forecasts are chained when the CPR is created (arrival at KA → Sequence 3 approval → return → Sequence 8 approval), using models that learned only from older CPRs. Forecast workload = CPRs the KA would hold on that day according to these dates; actual workload = CPRs the KA really held (Sequence 3 + Sequence 8, first round; rework is not forecast and not counted). Same CPRs and the same KA on both sides, so only the timing is compared.

    Forecast settings

    Choose which history the forecast learns from. Default = the analysis notebook. "Apply and retrain" tests the new setting on the latest months and shows its test MAE next to the default, so the effect is visible before it is relied on. Only CPRs allocated after the change use the new forecast; saved Key Account assignments do not change.

    Model selection in the dashboard (automatic)

    Same procedure as the analysis notebook: each candidate learns from older history and is checked on a 3-month validation window (2026-process CPRs); the lowest validation MAE is chosen, tested on the latest 3 months, then retrained on all history to forecast the queue.

    Rework risk: does the warning work?

    The risk model learns from older CPRs whose Sequence 8 is finished, then is checked on the CPRs of the latest months it has not seen. A useful warning sends back clearly more "High" CPRs than "Low" ones. AUC: 0.5 = no better than chance, 1.0 = perfect.

    Comparison of the four models (analysis notebook)

    Study in the Python notebook on CPR_Cleaned 2023–2026: each forecast is learned by Linear Regression, Random Forest, XGBoost and a Neural Network (MLP), plus an Ensemble of the best two. The model with the lowest validation MAE (Apr–Jun 2026) is chosen and then tested once on Jul–Sep 2026; "p" is the Wilcoxon test against the simple guess; the test MAE of the chosen model uses whole-day forecasts, as shown in the dashboard. The dashboard itself keeps choosing automatically between Linear Regression and XGBoost (the table above), retrained on the uploaded CPRHistory + CPRSummary.
